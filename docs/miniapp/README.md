# Predictor — Multi-Game Analyst / deliverables

Mini App — работающая часть бота, а не макет: страница вшита в бинарь и
отдаётся по `/app/`, данные приходят из собственного API бота, запуск
проверяется по подписи Telegram. Файлы из этой папки — исходные
дизайн-материалы, по которым она была собрана; где они разошлись с тем,
что реально работает, верить надо коду.

Поддерживаемые дисциплины — те же, что у бота: **CS2 и Dota 2**.
Дизайн-система рассчитана на большее число игр (accent-токены заведены и на
Valorant с LoL), но экраны показывают только те дисциплины, в которых у
человека действительно есть прогнозы.

## Что входит

- `TECH_SPEC_v2.md` — продуктово-техническая спецификация с multi-game расширением и ограничениями текущего backend.
- `DESIGN_SYSTEM.md` — обновлённая дизайн-система, игровые accent themes, адаптивность и правила data UI.
- `FIGMA_HANDOFF.md` — структура Figma, variables/components/Auto Layout и правила handoff.
- `../../internal/miniapp/static/` — интерактивный HTML/CSS/JS прототип пяти основных вкладок; вшивается в бинарь и отдаётся ботом по `/app/`.
- `../../figma/predictor-multigame-board.png` — обзор пяти мобильных экранов 390×844.
- `../../figma/v2/screens/` — длинные render-проверки экранов.
- `../../figma/v2/viewport-final/` — viewport-превью 390×844.
- `TEAM_LOGOS.md` — источники логотипов команд, приоритет и фолбэки.

## Запуск прототипа

Локально — статикой:

```bash
cd internal/miniapp/static
python -m http.server 8765
```

Открыть `http://localhost:8765`. В проде страницу отдаёт сам бот по
`https://<домен>/app/` — файлы вшиты в бинарь, отдельного деплоя статики нет. Логотипы подтягиваются с того же origin;
чтобы открыть прототип локально против развёрнутого бота, добавьте
`?api=https://<домен>` (и `&logos=hltv`, чтобы посмотреть вариант с HLTV). Telegram WebApp bridge подключается штатно; в обычном браузере platform calls имеют safe fallback.

## Один фильтр на всё приложение

Панель фильтров наверху — единственное место, где в приложении вообще есть
фильтр. Два ряда: дисциплина и чат. Оба приезжают с сервера из того, что у
человека реально есть, и ряд с одним вариантом не рисуется — фильтр из
одного пункта это мебель.

Выбор уезжает в каждый запрос двумя параметрами (`game`, `chat`), которые
все эндпоинты разбирают одним и тем же кодом. Поэтому экран не может
разойтись с другим экраном в том, что выбрано: ни один экран этого не
решает. Раньше каждый экран фильтровал себя сам, и «CS2» на истории и на
наградах означало разное.

## Доступ

По умолчанию закрыто для всех. Человек запрашивает доступ из бота, оператор
подтверждает; операторы бота освобождены от запроса — они его и выдают.
Приложение читает всю историю прогнозов, поэтому открывается только по
явному решению. Подробнее — `SECURITY.md`.

## Логотипы команд

Прототип больше не хранит захардкоженный список URL. Логотипы приходят из
собственного API бота — `GET /api/miniapp/v1/teams?game=<code>` — куда они
попадают из PandaScore (все игры, вместе с обычной синхронизацией матчей)
и из рейтинга HLTV (только CS2, вместе с еженедельным запросом рейтинга).
Какой из двух показывать для CS2, решает настройка чата; команда без
логотипа рисуется инициалами. Подробнее — `TEAM_LOGOS.md`.

## Ограничения данных

Дизайн не выдаёт за реальные метрики данные, которых текущий backend не хранит надёжно: карты, market/model probability, roster-change event, LAN/Online и формальный difficulty factor. Для новых дисциплин необходимо расширить domain model через `game_id`, game-specific match metadata и segment adapters.

## Настройки

Те же настройки, что бот предлагает в личных сообщениях, доступны и здесь —
и разделены так же, как там: **личные** и **по каждому чату, которым вы
управляете**. Никогда на одном экране вперемешку: именно поэтому в боте это
два разных меню, и перенести меню, потеряв разделение, — самый быстрый
способ дать человеку заглушить чат вместо себя.

Каждый контрол пишет сразу. Экран настроек с кнопкой «Сохранить» — это
экран, который можно покинуть в несохранённом состоянии; переключатель
здесь меняется на месте и возвращается обратно, если запись не прошла.

Право на изменение чата перепроверяется на **каждой** записи, а не берётся
из того, что показал список при открытии экрана: права могут отобрать, пока
приложение открыто, и показанный экран — не разрешение.

В боте намеренно осталось то, чему там место: назначение модераторов
(делается ответом на сообщение участника и вне разговора смысла не имеет) и
журнал изменений (это запись, а не настройка). Часовой пояс и имя в списках
показаны только для чтения — их ввод требует текстового диалога.

## Что где живёт

Каждая цифра существует в одном месте — экраны не повторяют друг друга:

| Экран | Отвечает на вопрос | Данные |
|---|---|---|
| Обзор | как я выступаю **сейчас** | точность, серия, форма последних, активные и последние завершённые прогнозы |
| Аналитика | **из чего** это складывается | разбор по дисциплинам; команды, которых читаете лучше и хуже — оба конца одного рейтинга |
| История | что именно я прогнозировал | лента; свой фильтр только «верно/ошибка», дисциплина и чат — в общей панели |
| Награды | что я выиграл и к чему иду | медали по чатам с турниром и датой, полный каталог достижений с прогрессом |
| Профиль | кто я и сколько всего | личность, итоги за всё время, источники данных |

«Сильнее всего» и «слабее всего» показываются, только когда дисциплин
больше одной и ни одна не выбрана: сравнивать одну игру саму с собой — это
назвать одно и то же дважды.

Один и тот же матч, спрогнозированный в нескольких чатах, — одна строка в
истории с пометкой, в скольких чатах он был: две одинаковые карточки
читаются как баг.
